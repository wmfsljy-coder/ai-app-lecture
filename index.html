AI로 학교 앱 만들기 · 2시간 강의안

웅천고 이정용 · 1년 동안 직접 만든 업무·수업 앱 경험 바탕

선생님 대상 2시간 강의, 수준별로 이렇게 접근합니다

핵심은 하나입니다. 코딩을 가르치지 않고, AI에게 "학교에서 필요한 것"을 정확히 말하는 법과 안전하게 쓰는 법을 가르친다. 초보자는 "오늘 하나 만들어 간다", 중급자는 "만든 앱을 오래 안심하고 운영한다"가 목표입니다.

제가 걸어온 길 (강의의 뼈대)

1단계채팅 AI로 글·문서

공문 초안, 안내문, 가정통신문, 수업 활동지

2단계HTML 한 장 도구

생기부 자동 생성기(나이스 바이트), 수행평가 채점 도우미

3단계시트 + 앱스스크립트

연구부 영수증 제출, 꾸러미 이수증, 연수 서명 등록부, 업무 흐름도

4단계깃허브 + 코딩 에이전트

과학 수업 허브 44단원, 웅천 서가(도서관 독서 프로그램)

5단계새 방식으로 옮기기

야자 도장판을 Next.js + Supabase + Vercel로 운영 중 전환

6단계여러 AI 한 팀 + 자동화

클로드가 만들고 코덱스가 검사, 브라우저 에이전트, 주소는 대시보드 한곳에

초보자 과정은 1~2단계에 '내 웹페이지를 인터넷에 올리기'까지, 중급자 과정은 3~6단계를 다룹니다. 깃허브 페이지가 두 과정을 잇는 다리입니다(초보자는 웹사이트에서 끌어다 놓기, 중급자는 명령과 코딩 에이전트로).

두 과정 공통 진행 원칙

1. 결과부터 보여 준다

첫 10분에 실제로 돌아가는 학교 앱을 휴대폰으로 직접 눌러 보게 한다. "나도 되겠다"가 먼저다.

2. 내 학교 일에서 시작

예제는 전부 연수 출석, 생기부, 모둠 편성, 형성평가처럼 선생님이 이번 주에 하는 일로 고른다.

3. 작게 만들고 하나씩 더하기

한 번에 다 시키지 않는다. 돌아가는 최소판을 만든 뒤 "이것도 해 줘"를 이어 붙인다.

4. 오류는 그대로 붙여 넣기

빨간 글씨가 나오면 해석하려 하지 말고 화면 그대로 AI에게 붙여 넣는다. 오류는 실패가 아니라 다음 주문서다.

5. 학생 정보는 먼저 지킨다

이름·학번은 AI 채팅에 넣지 않고, 공유 설정과 관리 화면 잠금을 매 실습 끝에 확인한다.

6. 무료 한도 안에서

학교 도구는 무료 도구로 충분하다. 다만 한도와 쉬면 멈추는 규칙을 미리 알려 준다.

강사가 준비할 것

초보자 과정

  • 시연용 앱 3개를 휴대폰 QR로 열 수 있게 준비(내 앱 주소 모음 대시보드)
  • 실습 5 완성본(연수 안내 웹페이지 + 출석 설문)을 미리 올려 두고 QR 띄우기(참가자가 먼저 눌러 보게)
  • 학교 와이파이에서 github.com·github.io·구글 설문지 접속 확인, 참가자에게 깃허브 미리 가입 안내
  • 참가자 수 x 2장 '내 업무 찾기' 쪽지(또는 이 페이지 마지막 단계)

중급자 과정

  • 일주일 전 안내: GitHub 계정, git·Node.js·GitHub CLI(gh) 설치, gh auth login, git config --global user.name/user.email, Claude Code 또는 Codex 로그인까지 미리
  • 일부러 버그를 넣은 연습 저장소 하나(실습 5)
  • 내 실제 운영 사례 화면: 작업일지, 검수 결과, 전환 체크리스트
  • 코딩 에이전트 유료 구독이 없는 참가자를 위한 짝 활동 계획

주문서(프롬프트) 모음

앱스스크립트 웹앱 예제: 입력을 시트에 바로 쌓기 (중급자 참고)

초보자 과정은 웹페이지 + 구글 설문지로 충분합니다. 설문지로는 모자랄 때(화면을 내 뜻대로, 낸 뒤 바로 집계 보여 주기, 서명 받기) 쓰는 다음 단계입니다. 연구부 영수증 제출, 연수 서명 등록부가 이 구조입니다.

  1. 구글 시트를 만들고, 주소의 /d/와 /edit 사이 글자(시트 ID)를 복사
  2. 확장 프로그램 → Apps Script → Code.gs에 ①을 붙여 넣고 맨 위 SHEET_ID에 시트 ID 넣기
  3. 왼쪽 + → HTML → 이름 index → ② 붙여 넣기 → 저장
  4. 배포 → 새 배포 → 웹 앱 → 실행: 나 / 액세스: 학교 계정끼리면 '조직 내', 학생 개인 기기면 '모든 사용자' → 권한 승인('확인되지 않은 앱'이면 고급 → 이동)
  5. 고칠 때는 '새 배포'가 아니라 배포 관리 → 연필 → 버전: 새 버전 (그래야 주소·QR이 그대로)

명령어 치트시트 (중급자)

명령뜻
git pull --rebase시작 전에 깃허브의 최신본을 받아 온다. 다른 PC·다른 AI가 고친 것과 부딪히지 않게.
git add -A → git commit -m "무엇을 왜"지금 상태를 기록(저장 지점). 잘못되면 여기로 되돌릴 수 있다.

git revert <번호>그 기록을 취소하는 새 기록을 만든다(안전한 되돌리기).
gh repo create 이름 --private --source . --push지금 폴더로 깃허브 비공개 저장소를 만들고 올린다.
claude그 폴더에서 Claude Code 시작. 첫 지시는 "CLAUDE.md를 읽고 시작해".

clasp push → clasp deploy -i <배포ID>앱스스크립트를 내 PC에서 올리고, 같은 주소로 새 버전 배포.
